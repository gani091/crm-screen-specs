# CRM 화면정의서 공통 지침

## 역할

이 문서는 CRM 기능별 화면정의서를 만들고 GitHub Pages로 공유할 때 공통으로 적용하는 운영 기준입니다. ScreenSpec의 상세 작성 문법은 라이브러리 저장소의 `SKILL.md`를 단일 출처로 사용합니다.

## 화면 ID

```text
SCR-{프로젝트 약어}-{화면 약어}-{3자리 번호}
```

- 기존 CRM 화면 ID 체계가 있으면 기존 체계를 우선합니다.
- 화면명은 한국어 명사구로 작성합니다.
- 화면 경로는 URL이 아니라 CRM 정보구조 기준으로 작성합니다.

## 버전 정책

- 최초 개발 공유본은 `v1`입니다.
- 공유 후 기능·정책·화면 흐름이 바뀌면 새 버전을 추가합니다.
- 오탈자라도 이미 개발 근거로 사용됐다면 기존 버전을 유지하고 새 버전에서 수정합니다.
- 각 버전 경로는 불변 링크로 취급합니다.
- 최신 링크는 편의를 위한 별칭이며 개발 근거 링크로 사용하지 않습니다.

## 상태 정책

- `draft`: 기획 작성 중, 개발 기준으로 사용 불가
- `review`: 유관부서 검토 중
- `approved`: 개발 기준 확정
- `deprecated`: 후속 버전으로 대체됨

## 공유 규칙

- 개발 티켓에는 반드시 `/vN/` 형식의 고정 링크를 기록합니다.
- 링크와 함께 버전, 화면 ID, 기준일을 기록합니다.
- 미확정 정책은 화면정의서에서 확정 정책과 분리하여 표시합니다.
- 빈 상태·로딩·오류는 정의하거나 해당 없음의 사유를 기록합니다.

## 변경 이력

기능별 `history.json`에 다음 내용을 남깁니다.

- 버전
- 상태
- 작성일
- 변경 요약
- 포함 화면 ID
- 대체하는 이전 버전
